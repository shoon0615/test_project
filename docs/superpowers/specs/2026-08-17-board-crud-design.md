# 게시판 CRUD 데모 설계

## 목표

`frontend/test/superpowers_framework`에 게시글의 목록 조회, 상세 조회, 작성, 수정, 삭제를 체험할 수 있는 프런트엔드 데모를 만든다. 데이터는 별도 백엔드 대신 `json-server`가 제공하는 REST API에 저장한다.

## 범위

포함하는 기능은 기본 CRUD와 필수 입력값 검증이다. 검색, 페이지네이션, 인증, 댓글, 첨부 파일, 권한 관리는 포함하지 않는다.

## 기술 구성

- Next.js 16 App Router
- React 19
- TypeScript
- Tailwind CSS 4
- `json-server`
- 화면 및 API 계층 테스트를 위한 프로젝트 호환 테스트 도구

Next.js 개발 서버는 기본 포트를 사용하고 `json-server`는 `http://localhost:4000`에서 실행한다. 개발자가 두 서버를 편리하게 시작할 수 있도록 개별 실행 명령과 통합 실행 명령을 제공한다.

## 데이터 모델

`db.json`의 `posts` 컬렉션에 다음 구조로 게시글을 저장한다.

```ts
type Post = {
  id: string;
  title: string;
  author: string;
  content: string;
  createdAt: string;
};
```

`title`, `author`, `content`는 사용자가 입력한다. `createdAt`은 생성 시 ISO 8601 문자열로 자동 기록하며 수정할 수 없다. `id`는 `json-server`가 생성한다.

## 라우팅과 화면

### `/`

게시글 목록을 최신 작성일순으로 표시한다. 각 항목은 제목, 작성자, 작성일을 보여주고 상세 화면으로 연결한다. 게시글이 없으면 빈 상태 안내와 작성 버튼을 표시한다.

### `/posts/new`

공통 게시글 폼을 작성 모드로 사용한다. 제목, 작성자, 내용은 공백만 입력할 수 없으며 검증 오류를 해당 입력 필드 가까이에 표시한다. 생성에 성공하면 새 게시글 상세 화면으로 이동한다.

### `/posts/[id]`

게시글 전체 내용을 표시하고 목록, 수정, 삭제 동작을 제공한다. 삭제 전에 확인을 요청하며 삭제 성공 후 목록으로 이동한다. 존재하지 않는 ID에는 안내와 목록 이동 링크를 표시한다.

### `/posts/[id]/edit`

기존 데이터를 불러와 공통 게시글 폼을 수정 모드로 사용한다. 작성일은 유지하며 수정 성공 후 해당 게시글 상세 화면으로 이동한다.

## 컴포넌트와 책임

- `PostList`: 게시글 컬렉션 렌더링과 빈 상태 표현
- `PostForm`: 작성·수정 공통 입력 UI, 클라이언트 검증, 제출 상태 표현
- `PostDetail`: 단일 게시글 정보와 수정·삭제 동작 표현
- `posts-api`: 목록, 상세, 생성, 수정, 삭제 HTTP 요청과 응답 정규화
- 라우트 컴포넌트: 각 화면의 데이터 로딩, 오류 상태, 이동 흐름 조정

각 UI 컴포넌트는 표현과 사용자 입력에 집중하고 HTTP 세부 구현은 `posts-api`에 한정한다. 이 경계로 API 동작과 화면 동작을 독립적으로 테스트할 수 있게 한다.

## 데이터 흐름

목록과 상세 화면은 진입 시 `posts-api`를 통해 데이터를 조회한다. 작성 및 수정 폼은 클라이언트 검증을 통과한 값만 API로 전송한다. 삭제는 사용자 확인 후 요청한다. 성공한 변경은 목적지 화면으로 이동해 서버의 최신 데이터를 다시 조회한다.

## 상태와 오류 처리

- 조회 중에는 레이아웃을 유지하는 로딩 메시지를 표시한다.
- 네트워크 또는 서버 오류에는 이해하기 쉬운 메시지와 재시도 동작을 제공한다.
- 제출 중에는 중복 요청을 막고 버튼 상태를 변경한다.
- 제출 실패 시 입력값을 유지하여 사용자가 다시 시도할 수 있게 한다.
- 존재하지 않는 게시글은 일반 서버 오류와 구분해 처리한다.
- 삭제 취소 시 어떠한 API 요청이나 화면 이동도 수행하지 않는다.

## UI 방향

읽기 편한 단일 콘텐츠 열을 중심으로 구성하고 목록, 폼, 상세 화면에 일관된 헤더와 버튼 스타일을 사용한다. 모바일부터 데스크톱까지 입력 필드, 긴 본문, 작업 버튼이 잘리지 않는 반응형 레이아웃을 제공한다. 키보드 포커스, 입력 레이블, 오류 연결 등 기본 접근성을 준수한다.

## 테스트와 완료 기준

- API 계층에서 모든 CRUD 메서드의 요청 방식, URL, 데이터 변환을 검증한다.
- 폼 필수값 검증과 제출 중 상태를 검증한다.
- 목록의 데이터·빈 상태·오류 상태를 검증한다.
- 상세 조회, 작성, 수정, 삭제의 주요 사용자 흐름을 검증한다.
- 삭제 확인 취소와 존재하지 않는 게시글 처리를 검증한다.
- 린트, 자동화 테스트, 프로덕션 빌드가 모두 성공해야 한다.
- Next.js와 `json-server`를 함께 실행해 실제 CRUD 흐름이 정상 동작해야 한다.

## 제외 사항

이 데모는 `json-server`를 로컬에서 실행하는 개발용 예제다. 운영 배포용 데이터 영속성, 동시성 제어, 사용자 인증, 보안 정책은 제공하지 않는다.
