# team-crud-system - 계획 문서

> 버전: 1.0.0 | 작성일: 2026-08-14 | 상태: 초안
> 프로젝트 레벨: Starter

---

## 1. 개요

### 1.1 목적

브라우저에서 팀 정보를 직접 등록, 조회, 수정, 삭제할 수 있는 간단한 Team CRUD 시스템을 만든다.

### 1.2 배경

현재 프로젝트는 Starter 레벨로 감지되었고, 별도의 백엔드나 데이터베이스 구조가 없다. 따라서 HTML, CSS, JavaScript만 사용해 정적 웹앱으로 구현하고, 데이터는 브라우저의 `localStorage`에 저장한다.

이 방식은 서버 없이 CRUD 흐름을 학습하고 검증하기에 적합하다.

## 2. 목표

### 2.1 주요 목표

- [ ] 팀 관리 화면을 만든다.
- [ ] 팀 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)를 지원한다.
- [ ] 팀 데이터를 브라우저에 저장해 새로고침 후에도 유지한다.
- [ ] 검색, 상태 필터, 입력 검증을 제공한다.
- [ ] 모바일과 데스크톱 화면에서 모두 사용할 수 있게 만든다.

### 2.2 하지 않을 일

- 서버 API를 만들지 않는다.
- 실제 데이터베이스를 연결하지 않는다.
- 로그인, 권한, 사용자 역할 기능은 만들지 않는다.
- 여러 사용자가 동시에 공유하는 실시간 협업 기능은 만들지 않는다.

## 3. 범위

### 3.1 포함 범위

- 팀 이름, 담당자, 인원 수, 상태, 설명을 가진 팀 목록
- 새 팀 등록 폼
- 기존 팀 수정 기능
- 삭제 전 확인 절차
- 팀 이름, 담당자, 설명 기준 검색
- 상태별 필터링
- 전체 팀, 활성 팀, 보류 팀 등 요약 카운트
- 반응형 화면 구성

### 3.2 제외 범위

- API 엔드포인트
- 서버 저장소 또는 외부 데이터베이스
- 인증 및 권한 관리
- 배포 자동화
- 테스트 자동화 스크립트

| ID | 요구사항 | 우선순위 | 상태 |

| FR-02 | 사용자는 저장된 팀 목록을 볼 수 있다. | 높음 | 대기 |
| FR-03 | 사용자는 기존 팀 정보를 수정할 수 있다. | 높음 | 대기 |
| FR-04 | 사용자는 팀을 삭제할 수 있다. | 높음 | 대기 |
| FR-05 | 사용자는 검색어로 팀을 찾을 수 있다. | 중간 | 대기 |
| FR-06 | 사용자는 팀 상태로 목록을 필터링할 수 있다. | 중간 | 대기 |

## 5. 비기능 요구사항

| 항목 | 기준 | 확인 방법 |
|------|------|-----------|
| 사용성 | 한 화면에서 등록, 검색, 목록 확인이 가능해야 한다. | 브라우저 수동 확인 |
| 반응형 | 모바일 폭에서도 폼과 목록이 겹치지 않아야 한다. | 브라우저 화면 크기 변경 확인 |
| 저장 | 새로고침 후에도 데이터가 유지되어야 한다. | 등록 후 새로고침 확인 |
| 접근성 | 입력 요소에 라벨이 있어야 하고 키보드 포커스가 보여야 한다. | 수동 확인 |

## 6. 성공 기준

- [ ] 사용자가 팀을 추가할 수 있다.
- [ ] 사용자가 저장된 모든 팀을 볼 수 있다.
- [ ] 사용자가 기존 팀을 수정할 수 있다.
- [ ] 사용자가 팀을 삭제할 수 있다.
- [ ] 팀 데이터가 `localStorage`를 통해 새로고침 후에도 유지된다.
- [ ] 검색과 상태 필터가 동작한다.
- [ ] 모바일과 데스크톱 화면에서 주요 UI가 깨지지 않는다.

## 9. 아키텍처 결정

| 결정 항목 | 선택 | 이유 |
|-----------|------|------|
| 구현 방식 | 정적 HTML/CSS/JavaScript | Starter 레벨에 맞고 서버 없이 실행 가능하다. |
| 데이터 저장 | `localStorage` | 브라우저만으로 CRUD 저장 흐름을 구현할 수 있다. |
| 화면 구성 | 단일 페이지 | CRUD 학습 목적에 맞고 파일 구조가 단순하다. |
| 스타일링 | Plain CSS | 별도 의존성 없이 바로 실행 가능하다. |
