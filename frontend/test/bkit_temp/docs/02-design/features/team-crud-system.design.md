## 1. 무엇을 만드는가?

팀 정보를 관리하는 단일 페이지 웹앱을 만든다. 사용자는 팀을 등록하고, 목록을 확인하고, 기존 팀을 수정하고, 팀을 삭제할 수 있다. 검색과 상태 필터를 통해 원하는 팀을 빠르게 찾을 수 있다.

데이터는 서버가 아니라 브라우저의 `localStorage`에 저장한다.

## 2. 페이지

| 페이지 | 경로 | 설명 |
|--------|------|------|
| 팀 관리 | `/index.html` | 팀 CRUD 기능을 제공하는 메인 화면 |

## 3. 화면 구조

```text
+------------------------------------------------+
| 헤더: 화면 제목, 간단한 설명                    |
+------------------------------------------------+
| 요약 영역: 전체 팀, 활성 팀, 보류 팀 카운트      |
+----------------------+-------------------------+
| 팀 입력/수정 폼      | 검색, 상태 필터, 팀 목록 |
|                      |                         |
+----------------------+-------------------------+
```

모바일 화면에서는 입력 폼과 목록 영역을 위아래로 배치한다.

## 4. 주요 컴포넌트

| 컴포넌트 | 역할 |
|----------|------|
| 헤더 | 앱 이름과 현재 화면의 목적을 보여준다. |
| 요약 카드 | 전체 팀 수, 활성 팀 수, 보류 팀 수를 보여준다. |
| 팀 폼 | 새 팀 등록과 기존 팀 수정을 담당한다. |
| 검색/필터 영역 | 검색어 입력과 상태 필터를 제공한다. |
| 팀 목록 | 저장된 팀 목록과 수정/삭제 버튼을 보여준다. |
| 빈 상태 메시지 | 저장된 팀이 없거나 검색 결과가 없을 때 안내한다. |

## 5. 데이터 모델

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `id` | string | 예 | 팀을 구분하는 고유값 |
| `name` | string | 예 | 팀 이름 |
| `owner` | string | 예 | 팀 담당자 또는 리더 |
| `members` | number | 예 | 팀 인원 수, 1 이상 999 이하 |
| `status` | string | 예 | `active`, `paused`, `archived` 중 하나 |
| `description` | string | 아니오 | 팀 설명 |
| `createdAt` | string | 예 | 생성 일시, ISO 문자열 |

## 6. 상태 값

| 값 | 화면 표시 | 의미 |
|----|-----------|------|
| `active` | 활성 | 현재 운영 중인 팀 |
| `paused` | 보류 | 잠시 멈춰 있거나 준비 중인 팀 |
| `archived` | 보관 | 현재 운영하지 않지만 기록으로 남긴 팀 |

## 7. 사용자 동작 흐름

### 7.1 팀 등록

1. 사용자가 팀 이름, 담당자, 인원 수, 상태, 설명을 입력한다.
2. 필수값과 인원 수 범위를 검사한다.
3. 통과하면 새 `id`와 `createdAt`을 추가한다.
4. 팀 목록에 추가하고 `localStorage`에 저장한다.
5. 폼을 초기화하고 목록을 다시 그린다.

### 7.2 팀 조회

1. 페이지가 열리면 `localStorage`에서 팀 목록을 읽는다.
2. 저장된 값이 없으면 빈 배열로 시작한다.
3. 요약 카드와 팀 목록을 화면에 표시한다.

### 7.3 팀 수정

1. 사용자가 목록에서 수정 버튼을 누른다.
2. 선택한 팀 데이터를 폼에 채운다.
3. 폼 제목과 버튼 문구를 수정 모드로 바꾼다.
4. 저장하면 같은 `id`의 팀 데이터를 갱신한다.
5. `localStorage`에 다시 저장하고 폼을 초기화한다.

### 7.4 팀 삭제

1. 사용자가 삭제 버튼을 누른다.
2. 브라우저 확인창으로 삭제 의사를 확인한다.
3. 확인하면 해당 `id`의 팀을 목록에서 제거한다.
4. `localStorage`에 다시 저장하고 목록을 다시 그린다.

### 7.5 검색과 필터

1. 검색어가 바뀌면 팀 이름, 담당자, 설명을 기준으로 목록을 필터링한다.
2. 상태 필터가 바뀌면 선택한 상태에 해당하는 팀만 보여준다.
3. 검색어와 상태 필터를 함께 적용한다.

## 8. 입력 검증 규칙

| 입력값 | 규칙 | 오류 메시지 기준 |
|--------|------|------------------|
| 팀 이름 | 비어 있으면 안 된다. | 팀 이름을 입력하라고 안내한다. |
| 담당자 | 비어 있으면 안 된다. | 담당자를 입력하라고 안내한다. |
| 인원 수 | 1 이상 999 이하 숫자여야 한다. | 올바른 인원 수를 입력하라고 안내한다. |
| 상태 | 정해진 상태 중 하나여야 한다. | 상태를 선택하라고 안내한다. |

## 10. 구현 기준

### 10.1 HTML

- `main` 영역 안에 요약, 폼, 목록을 배치한다.
- 모든 입력 요소에 `label`을 연결한다.
- 버튼 텍스트는 동작을 명확히 표현한다.

### 10.2 CSS

- 데스크톱에서는 폼과 목록을 2열로 배치한다.
- 모바일에서는 1열로 쌓는다.
- 버튼, 입력창, 카드에 명확한 포커스 상태를 둔다.
- 카드 안에 다시 카드를 중첩하지 않는다.

### 10.3 JavaScript

- 상수 이름은 대문자 스네이크 케이스를 사용한다.
- 함수 이름은 camelCase를 사용한다.
- `teams` 배열을 화면 상태의 기준으로 사용한다.
- 저장과 렌더링은 별도 함수로 분리한다.

## 11. 주요 함수 설계

| 함수 | 역할 |
|------|------|
| `loadTeams()` | `localStorage`에서 팀 목록을 읽는다. |
| `saveTeams()` | 현재 팀 목록을 `localStorage`에 저장한다. |
| `renderTeams()` | 검색/필터 결과에 맞춰 목록을 그린다. |
| `renderSummary()` | 요약 카운트를 갱신한다. |
| `validateForm()` | 폼 입력값을 검사한다. |
| `handleSubmit()` | 등록 또는 수정 저장을 처리한다. |
| `startEdit()` | 선택한 팀을 수정 모드로 불러온다. |
| `deleteTeam()` | 선택한 팀을 삭제한다. |
| `resetForm()` | 폼을 초기 상태로 되돌린다. |

## 12. 확인 계획

- 팀 추가 후 목록에 표시되는지 확인한다.
- 새로고침 후 데이터가 유지되는지 확인한다.
- 수정 버튼으로 폼이 수정 모드로 바뀌는지 확인한다.
- 수정 저장 후 같은 팀이 갱신되는지 확인한다.
- 삭제 확인 후 팀이 제거되는지 확인한다.
- 검색어와 상태 필터가 함께 적용되는지 확인한다.
- 모바일 폭에서 화면 요소가 겹치지 않는지 확인한다.
