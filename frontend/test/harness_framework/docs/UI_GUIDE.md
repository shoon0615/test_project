# UI 디자인 가이드

## 디자인 원칙
1. URL 입력이 첫 화면의 유일한 주 행동이어야 한다.
2. 결론보다 근거를 숨기지 않는다. 모든 인사이트는 언급량과 대표 댓글로 확인 가능해야 한다.
3. 장식보다 정보 계층과 읽기 편한 긴 문장에 집중한다.
4. 감정 상태를 색만으로 전달하지 않는다.

## 화면 구조
```text
Header: Comment Lens · 최근 리포트

Intro: "댓글 300개를 읽는 대신, URL 하나로 핵심만 보세요."
[ YouTube URL 입력                              ] [분석하기]
개인정보 안내 / 입력 오류

Video summary + 수집/분석 진행 상태

Report
├── 한 줄 총평 / 표본 크기 / 분석 시각
├── 감정 분포
├── 잘하고 있는 점
├── 개선할 점
├── 주요 주제
├── 다음 콘텐츠 아이디어
└── 대표 댓글

[다른 영상 분석] [PDF로 저장]
```

## 반응형 레이아웃
- 전체 콘텐츠: `max-w-6xl mx-auto px-4 md:px-8`
- 입력 영역과 총평: 최대 `max-w-3xl`
- 데스크톱 리포트: 강점/개선점 2열, 나머지는 정보량에 따라 1~2열
- 모바일: 모두 1열, URL 입력과 버튼을 세로 배치
- 차트는 장식용 원형 게이지보다 수치 비교가 쉬운 100% 누적 막대를 사용

## 컴포넌트

### URL 입력
```text
h-12 rounded-md border border-[#CFCFC7] bg-white px-4
focus-visible:ring-2 focus-visible:ring-[#D92D20]
```
- 실제 `<label>`을 제공한다.
- placeholder: `https://www.youtube.com/watch?v=...`
- 붙여넣은 직후 지원 URL인지 검증하되, 분석은 버튼이나 Enter로 시작한다.

### 주요 버튼
```text
h-12 rounded-md bg-[#D92D20] px-5 font-medium text-white
hover:bg-[#B42318] disabled:opacity-50
```
- 분석 중에는 spinner와 `댓글 가져오는 중`처럼 현재 단계를 표시한다.
- 버튼 폭이 상태 문구에 따라 흔들리지 않게 최소 너비를 둔다.

### 리포트 카드
```text
rounded-lg border border-[#DFDFD8] bg-white p-5 md:p-6
```
- 카드 전체를 클릭 영역으로 만들지 않는다.
- 강점은 왼쪽 초록 선, 개선점은 왼쪽 붉은 선으로 구분하되 제목 라벨을 항상 병기한다.
- 대표 댓글은 인용문, 좋아요 수와 감정 라벨만 표시하고 작성자 정보는 표시하지 않는다.

### 진행 상태
- `URL 확인 → 영상 확인 → 댓글 수집 → 반응 분석 → 리포트 작성`의 다섯 단계를 텍스트로 표시한다.
- 실제 진행률을 알 수 없을 때 가짜 백분율을 표시하지 않는다.
- 현재까지 수집한 댓글 수는 실시간으로 표시할 수 있다.
- 항상 보이는 `취소` 버튼을 제공하고, 취소 후 입력값을 유지한다.

### 오류/빈 상태
- 원인, 사용자가 할 수 있는 다음 행동, 재시도 버튼을 한 영역에 제공한다.
- 오류를 toast로만 표시하지 않는다.
- 댓글 비활성화와 API 할당량 소진을 일반 네트워크 오류와 구분한다.
- 재시도 가능한 오류에만 재시도 버튼을 표시한다. 설정 오류와 댓글 비활성화에는 의미 없는 재시도를 권하지 않는다.
- 진단 ID는 세부 정보 disclosure 안에 제공하고 API 원문 메시지나 키는 노출하지 않는다.

### 부분 성공
- 상단 총평보다 먼저 `댓글 일부만 수집됨` 경고를 표시한다.
- 수집된 댓글 수, 중단된 단계와 결과가 전체 댓글을 대표하지 않는다는 설명을 제공한다.
- PDF에도 부분 결과 경고와 분석 기준이 포함되어야 한다.

### 표본 부족
- 차트 숫자를 과장해 확대하지 않고 수집/유효/제외 댓글 수를 함께 표시한다.
- 강점·개선점 카드의 빈칸을 placeholder 조언으로 채우지 않는다.
- 최소 표본 또는 최소 언급 기준을 충족하지 못한 이유를 한 문장으로 설명한다.

## 타이포그래피
| 용도 | 스타일 |
|---|---|
| 페이지 제목 | `text-3xl md:text-4xl font-semibold tracking-tight` |
| 한 줄 총평 | `text-xl md:text-2xl font-medium leading-snug` |
| 섹션 제목 | `text-base font-semibold` |
| 본문 | `text-sm md:text-base leading-7` |
| 메타데이터 | `text-xs text-[#73736C]` |

한국어 가독성을 위해 시스템 폰트 스택을 사용하고 본문 최소 크기는 14px로 유지한다.

## 애니메이션
- 진행 단계 전환과 리포트 등장에 150~200ms opacity transition만 허용한다.
- `prefers-reduced-motion`을 존중한다.
- 무한 펄스, 글로우, 장식용 parallax는 사용하지 않는다.

## 인쇄/PDF
- 헤더, URL 입력, 재분석 버튼과 진행 상태를 숨긴다.
- 배경을 흰색으로 바꾸고 데이터 색상은 인쇄에서도 식별 가능한 명암을 유지한다.
- 카드가 페이지 중간에서 잘리지 않도록 `break-inside: avoid`를 적용한다.
