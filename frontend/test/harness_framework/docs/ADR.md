# Architecture Decision Records

## 철학
입력부터 근거 있는 결과까지의 시간을 최소화한다. 서버가 없는 제약을 숨기지 않으며, 사용자 댓글과 비밀 키를 불필요한 제3자에게 보내지 않는다. 정확해 보이는 문장보다 검증 가능한 통계와 대표 댓글을 우선한다.

---

### ADR-001: Vite 기반 정적 React SPA
**결정**: React, TypeScript와 Vite로 빌드한 정적 SPA를 사용한다.

**이유**: 로그인, 서버 렌더링, 데이터베이스가 필요 없고 분석도 브라우저에서 완료된다. 정적 호스팅으로 배포와 운영 복잡도를 최소화할 수 있다.

**트레이드오프**: 비밀 키를 안전하게 보관하거나 장시간 백그라운드 작업을 실행할 수 없고, 구형/저사양 기기의 분석 성능에 영향을 받는다.

### ADR-002: YouTube Data API를 브라우저에서 직접 호출
**결정**: URL에서 영상 ID를 추출한 뒤 브라우저가 YouTube Data API v3를 직접 호출한다.

**이유**: 서버 없이 URL만으로 공개 댓글을 수집할 수 있는 공식 경로다.

**트레이드오프**: 빌드에 포함된 API 키는 공개된다. 키를 비밀로 취급하지 않고 YouTube Data API 범위, 배포 도메인 HTTP referrer, 일일 할당량으로 피해 범위를 제한한다. 이러한 공개 키 운영을 받아들일 수 없다면 자체 서버가 필수다.

### ADR-003: 결정론적 브라우저 분석으로 MVP 구성
**결정**: 한국어/영어 감정 사전, 문맥 규칙, 주제 키워드와 리포트 템플릿을 Web Worker에서 실행한다.

**이유**: 외부 LLM 키나 댓글의 제3자 전송 없이 빠르고 재현 가능한 리포트를 만들 수 있다. 각 결과를 언급량과 댓글 원문으로 설명하기도 쉽다.

**트레이드오프**: 반어법, 신조어와 복합 문맥 정확도는 대형 모델보다 낮고, 규칙과 사전을 지속적으로 개선해야 한다. 결과 화면에 표본 크기와 분석 한계를 명시한다.

### ADR-004: 분석 댓글을 최대 300개로 제한
**결정**: MVP 한 번의 분석에서 상위 댓글을 최대 300개 수집한다.

**이유**: 브라우저 성능, API 페이지네이션 시간과 빠른 결과 사이의 균형을 맞춘다. 개인 크리에이터가 반복 반응을 파악하기에는 충분한 초기 표본이다.

**트레이드오프**: 댓글이 매우 많은 영상에서 전체 여론을 대표하지 못할 수 있다. 리포트에 `상위 댓글 300개 기준`과 정렬 방식을 명확히 표시한다.

### ADR-005: 근거 우선 리포트
**결정**: 모든 강점, 개선점과 콘텐츠 아이디어는 최소 언급 기준을 충족해야 하며 대표 댓글 ID를 포함한다.

**이유**: 생성형 문장처럼 그럴듯하지만 근거 없는 조언을 방지하고 사용자가 결과를 직접 검증할 수 있다.

**트레이드오프**: 댓글 수가 적거나 의견이 분산된 영상에서는 인사이트 수가 3개보다 적을 수 있다. 이 경우 내용을 채워 넣지 않고 표본 부족을 표시한다.

### ADR-006: 로컬에 최근 리포트만 저장
**결정**: 스키마 버전을 포함한 최근 리포트 5개를 `localStorage`에 저장하고 작성자 식별 정보는 수집하지 않는다.

**이유**: 계정이나 데이터베이스 없이 재방문 편의를 제공한다.

**트레이드오프**: 다른 기기와 동기화되지 않고 브라우저 데이터 삭제 시 사라진다. 저장 공간 제한에 대비해 오래된 항목부터 제거한다.

### ADR-007: 관련도순 최상위 댓글을 기본 표본으로 사용
**상태**: 승인

**결정**: `commentThreads.list`에 `order=relevance`, `maxResults=100`, `textFormat=plainText`를 명시하고 최대 3페이지를 수집한다. 사용자가 최신순으로 전환하면 새 분석으로 취급한다.

**이유**: 관련도순은 제한된 300개 안에서 반응이 크고 의미 있는 댓글을 발견하기 쉽다. API 기본값은 최신순이므로 명시해야 재현 가능한 제품 동작이 된다.

**트레이드오프**: 이는 전체 댓글의 무작위 표본이 아니며 인기·초기 댓글에 편향될 수 있다. 리포트에 정렬과 `상위 댓글 기준`을 표시하고 감정 비율을 전체 시청자 여론으로 표현하지 않는다.

**대안**: 최신순만 사용하면 최근 피드백에는 유리하지만 오래된 대표 반응을 놓친다. 무작위 표본은 API가 직접 지원하지 않아 전체 페이지 수집이 필요하므로 MVP 성능·quota 목표와 맞지 않는다.

### ADR-008: API 키 노출 위험을 명시적으로 수용하되 운영 제한 적용
**상태**: 조건부 승인

**결정**: 브라우저의 공개 API 키를 YouTube Data API 전용, HTTP referrer 제한, 환경별 분리, 일일 quota와 알림으로 방어한다. 헤더로 키를 전달하고 저장소·로그에 포함하지 않는다.

**이유**: `서버 없음`과 `URL만 입력`을 동시에 만족시키려면 브라우저가 인증된 YouTube API 요청을 해야 한다.

**트레이드오프**: referrer 제한은 위험을 줄일 뿐 키를 비밀로 만들지 않으며 허용된 출처 악용과 quota 고갈 위험이 남는다. 공개 베타 이전에 이 잔여 위험을 제품 소유자가 재승인해야 한다.

**재검토 트리거**: quota 악용, 유료화, 사용자별 제한, 비밀 기반 AI API, 안정적인 SLA 중 하나가 필요해지면 최소 API 프록시/서버 구조로 전환한다.

### ADR-009: Web Worker와 job ID로 분석 격리
**상태**: 승인

**결정**: CPU 작업은 전용 Worker에서 수행하며 모든 요청·응답에 `jobId`를 넣는다. 취소/교체된 job의 결과는 reducer가 폐기한다.

**이유**: 300개 댓글의 정규화와 분류가 입력, 취소와 접근성 UI를 멈추지 않게 하고 비동기 race로 잘못된 영상 결과가 표시되는 것을 막는다.

**트레이드오프**: Worker 번들, 메시지 스키마, 구조화 복사와 crash 복구가 추가된다. 테스트는 fake Worker와 실제 Worker 통합 경로를 모두 포함해야 한다.

### ADR-010: 제한적 재시도와 부분 성공
**상태**: 승인

**결정**: 429와 5xx만 jitter backoff로 최대 2회 재시도한다. 첫 댓글 페이지 이후 transient 실패가 발생했고 30개 이상 수집했다면 경고가 포함된 부분 리포트를 허용한다.

**이유**: 일시적 장애로 이미 수집한 유용한 표본을 버리지 않되, 무제한 재시도로 quota와 대기 시간을 낭비하지 않는다.

**트레이드오프**: 부분 리포트의 표본 크기가 분석마다 다를 수 있다. 인증, 권한, quota, 잘못된 요청 오류는 부분 성공으로 감추지 않으며 리포트에 수집 상태를 영구 기록한다.

### ADR-011: 답글과 작성자 메타데이터 제외
**상태**: 승인

**결정**: MVP는 공개 최상위 댓글의 텍스트, 좋아요 수와 게시 시각만 사용한다. 답글과 작성자 이름·프로필·채널 ID는 요청·저장·분석하지 않는다.

**이유**: `commentThread` 응답의 답글은 전체 답글을 보장하지 않아 별도 요청이 필요하고, 작성자 정보는 피드백 분석에 불필요한 개인정보와 편향을 추가한다.

**트레이드오프**: 대화 맥락, 크리에이터 답변과 답글에서 나타나는 합의/반박을 놓친다. 답글 지원은 별도 quota·표본 정의·개인정보 검토가 완료된 후 새 ADR로 결정한다.

### ADR-012: 감정 비율에는 좋아요 가중치를 사용하지 않음
**상태**: 승인

**결정**: 각 유효 댓글은 감정 비율에서 동일한 1표다. 좋아요 수는 `log1p` 상한 가중치로 대표 댓글 순위에만 반영한다.

**이유**: 좋아요를 감정 집계에 사용하면 오래 노출된 댓글과 이미 인기 있는 댓글 하나가 전체 결과를 지배할 수 있다.

**트레이드오프**: 커뮤니티의 동의 강도를 감정 비율에 직접 반영하지 않는다. 대신 대표 댓글에 좋아요 수를 표시해 사용자가 별도로 해석하게 한다.

### ADR-013: 최소 표본과 최소 근거 기준
**상태**: 승인

**결정**: 유효 표본 10개 미만에서는 순위형 인사이트를 만들지 않는다. 개별 인사이트는 `max(3, ceil(유효 표본 × 0.05))`개 이상의 서로 다른 댓글을 요구한다.

**이유**: 댓글 한두 개를 채널 전체의 강점이나 개선점으로 과장하지 않고 템플릿이 빈칸을 허위 내용으로 채우는 것을 막는다.

**트레이드오프**: 작은 영상은 감정 카운트만 보고 구체적인 조언을 받지 못할 수 있다. 임계값은 초기 품질 평가 후 버전과 함께 조정한다.

### ADR-014: 런타임 스키마 검증과 버전 저장
**상태**: 승인

**결정**: YouTube 응답, Worker 메시지와 localStorage 데이터는 경계에서 검증한다. 리포트에 `schemaVersion`과 `analysisVersion`을 기록한다.

**이유**: 외부 응답 변경, 저장 데이터 손상, 오래된 탭과 Worker 불일치가 앱 전체 장애나 잘못된 집계로 이어지지 않게 한다.

**트레이드오프**: validator 코드와 마이그레이션 정책이 추가된다. 검증 실패는 해당 데이터만 격리하고 사용자에게 복구 경로를 제공한다.

### ADR-015: 운영 사용자 추적 도구를 MVP에서 사용하지 않음
**상태**: 승인

**결정**: 자체 analytics, session replay와 외부 오류 추적 SDK를 넣지 않는다. 개발 모드의 개인정보 없는 로컬 진단과 자동 fixture benchmark만 사용한다.

**이유**: 서버 없는 개인정보 최소화 약속을 지키고 URL/댓글이 제3자 telemetry로 유출되는 경로를 제거한다.

**트레이드오프**: 실제 실패율, 브라우저 분포와 분석 소요 시간을 중앙에서 볼 수 없다. 운영 관측이 필요해지면 이벤트 allowlist, 데이터 보존, 동의와 개인정보 문서를 포함한 별도 ADR이 필요하다.

### ADR-016: 오류를 HTTP 상태가 아닌 제품 오류 코드로 정규화
**상태**: 승인

**결정**: API/네트워크/Worker/저장 오류를 단계, 재시도 가능성, 안전한 진단 ID가 포함된 `AppError`로 변환하고 UI는 이 코드만 소비한다.

**이유**: 같은 403도 댓글 비활성화, quota, 키 제한처럼 사용자 행동이 다르며 브라우저 네트워크 오류는 세부 원인을 항상 구분할 수 없다.

**트레이드오프**: 매핑 테이블을 공식 API 변경에 맞춰 유지해야 한다. 알 수 없는 reason은 원문을 노출하지 않고 상위 범주의 안전한 fallback으로 처리한다.

### ADR-017: localStorage는 편의 기능이며 분석 성공 조건이 아님
**상태**: 승인

**결정**: 저장 실패는 현재 리포트를 실패로 바꾸지 않는다. 손상된 항목은 격리하고 용량 초과 시 오래된 항목 제거 후 한 번만 재시도한다.

**이유**: private browsing, 사용자 정책과 브라우저 한도 때문에 localStorage는 항상 사용 가능하다고 가정할 수 없다.

**트레이드오프**: 저장되지 않은 결과는 탭 종료 시 사라진다. UI에서 비차단 경고와 PDF 저장 대안을 제공한다.

### ADR-018: 서버 없는 범위에서 자유 형식 생성형 AI를 사용하지 않음
**상태**: 승인

**결정**: MVP 리포트 문장은 버전 관리되는 템플릿으로 생성하며 OpenAI, Gemini 등 비밀 키 또는 원격 추론이 필요한 API를 브라우저에서 직접 호출하지 않는다.

**이유**: 비밀 키 노출, 댓글의 제3자 전송, 비용 통제와 비결정적 결과가 현재 제품 원칙과 충돌한다.

**트레이드오프**: 표현 다양성과 복합 맥락 해석력이 제한된다. 생성형 AI가 핵심 요구가 되면 동의·보존·비용·안전 정책과 서버 프록시를 함께 설계한다.

## 미해결 사항과 결정 시점
| 항목 | 현재 기본값 | 결정 시점 |
|---|---|---|
| 대표 댓글 원문 localStorage 저장 | 대표 댓글만 저장 | 공개 출시 전 정책/UX 검토 |
| 감정·주제 임계값 | PRD 초기 기준 | 라벨 평가셋 확보 후 튜닝 |
| 공개 API 키 잔여 위험 | 제한 적용 후 수용 | 공개 베타 go/no-go |
| 분석 사전 라이선스 | 자체/호환 라이선스만 | 구현 의존성 선택 전 |
| CSP의 정적 호스트별 문법 | 최소 정책 | 배포 플랫폼 선정 시 |
| YouTube 필수 고지/개인정보 문서 | 출시 gate | 공개 URL 배포 전 |
