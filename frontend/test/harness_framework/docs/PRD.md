# PRD: Comment Lens

## 한 줄 정의
유튜브 영상 URL 하나를 입력하면 공개 댓글을 분석해 시청자 반응, 잘하고 있는 점, 개선할 점을 한 화면의 리포트로 보여주는 비로그인 웹 앱.

## 목표
- 크리에이터가 댓글을 하나씩 읽지 않고도 전체 반응을 1분 안에 파악한다.
- 단순 긍정/부정 비율을 넘어 반복되는 칭찬과 실행 가능한 개선점을 제공한다.
- 가입, 설치, 서버 저장 없이 URL 입력만으로 분석을 시작한다.

## 핵심 사용자
- 댓글이 많아 피드백을 정리하기 어려운 1인 유튜브 크리에이터
- 업로드한 영상의 반응을 빠르게 검토하는 콘텐츠 마케터
- 다음 영상의 소재를 댓글에서 찾으려는 채널 운영자

## 핵심 사용자 흐름
1. 사용자가 YouTube 일반 영상, Shorts 또는 단축 URL을 붙여넣는다.
2. 앱이 URL을 검증하고 영상 ID를 추출한다.
3. 썸네일, 제목과 공개 댓글을 가져오며 수집/분석 진행 상태를 표시한다.
4. 댓글별 감정과 피드백 주제를 브라우저 안에서 분석한다.
5. 같은 화면에 요약 리포트를 표시한다.
6. 사용자는 대표 댓글을 근거로 확인하고 리포트를 인쇄/PDF 저장한다.

## 문제 정의와 제품 원칙

### 해결하려는 문제
- 댓글 수가 많을수록 크리에이터는 반복되는 의견과 소수의 강한 의견을 구분하기 어렵다.
- 단순 감정 비율은 무엇을 유지하고 무엇을 바꿔야 하는지 알려주지 못한다.
- 범용 LLM 요약은 근거 댓글, 표본과 분석 한계를 숨기기 쉬워 결과를 검증하기 어렵다.

### 제품 원칙
1. **URL에서 결과까지 한 흐름**: 설정 화면이나 회원가입으로 사용자를 우회시키지 않는다.
2. **근거 우선**: 모든 결론은 표본 수, 언급 수와 대표 댓글로 역추적 가능해야 한다.
3. **정직한 불확실성**: 표본 부족, 지원하지 않는 언어와 낮은 신뢰도를 숨기지 않는다.
4. **로컬 우선**: 외부로 보내야 할 데이터와 저장 기간을 최소화한다.
5. **복구 가능성**: 실패 원인과 사용자가 취할 수 있는 다음 행동을 항상 제공한다.

## 범위와 용어
- **댓글**: `commentThreads.list`가 반환한 공개된 최상위 댓글. 답글은 포함하지 않는다.
- **수집 댓글 수**: API에서 받은 댓글 수. 분석 제외 댓글도 포함한다.
- **유효 표본 수**: 중복, 스팸, 분석 불가능한 짧은 텍스트를 제외하고 집계에 사용한 댓글 수.
- **언급 수**: 특정 주제로 분류된 유효 댓글 수. 한 댓글이 여러 주제를 언급할 수 있으므로 주제 언급 수 합은 표본 수보다 클 수 있다.
- **감정 비율**: 유효 표본을 분모로 한 댓글 단위 비율. 좋아요 가중치는 대표 댓글 순위에만 사용하고 비율에는 사용하지 않는다.
- **대표 댓글**: 같은 주제 안에서 중복되지 않고 신뢰도가 높으며 반응을 잘 설명하는 원문 댓글.
- **관련도순 표본**: YouTube가 `order=relevance`로 반환한 최상위 댓글 최대 300개. 전체 댓글의 무작위·통계적 대표 표본을 의미하지 않는다.

## MVP 핵심 기능

### 1. URL 입력과 영상 확인
- `FR-URL-01` 앞뒤 공백, URL 중간 추적 파라미터, 모바일 도메인과 공유 URL을 안전하게 정규화한다.
- `youtube.com/watch`, `youtu.be`, `youtube.com/shorts` URL을 지원한다.
- `music.youtube.com/watch`, `m.youtube.com/watch`, `youtube.com/live/{id}`도 같은 영상 ID 규칙으로 지원한다.
- 재생목록 URL은 `v`가 있으면 해당 영상만 분석하고, 재생목록 전체를 분석하지 않는다고 표시한다.
- 시작 시간, `si`, `feature`, `list`, `index` 등 분석과 무관한 파라미터는 무시한다.
- 영상 ID는 정확히 11자의 허용 문자(`A-Z`, `a-z`, `0-9`, `_`, `-`)만 수용한다.
- 채널, 재생목록만 있는 URL, 스튜디오 URL, 검색 URL, 임의 호스트, JavaScript URL은 거부한다.
- 잘못된 URL, 비공개 영상, 댓글 비활성화, API 할당량 초과를 구분해 안내한다.
- 분석 전에 영상 제목, 채널명, 썸네일을 표시해 대상 영상을 확인시킨다.
- 붙여넣기는 자동으로 네트워크 요청을 시작하지 않는다. 버튼 또는 Enter로 명시적으로 시작한다.
- 입력값은 최대 2,048자로 제한하고 화면에는 안전한 텍스트로만 표시한다.

### 2. 공개 댓글 수집
- YouTube Data API v3를 사용해 상위 댓글을 최대 300개 수집한다.
- `maxResults=100`, `textFormat=plainText`, `order=relevance`를 명시하고 최대 3페이지를 순차 수집한다.
- 기본 정렬은 관련도순이며 최신순(`order=time`)으로 다시 분석할 수 있다. 리포트에 선택된 정렬 기준을 기록한다.
- 동일 영상·동일 정렬의 분석 버튼 연타는 하나의 작업으로 병합하고, 다른 영상 분석 시작 시 이전 요청과 Worker 작업을 취소한다.
- 300개에 도달하거나 `nextPageToken`이 없거나 사용자가 취소하면 수집을 중단한다.
- 페이지 2~3에서 일시적 실패가 나면 댓글을 30개 이상 수집했고 분석 후 유효 표본이 10개 이상인 경우에만 부분 리포트를 허용하고 `일부 댓글 기준` 경고를 표시한다. 어느 기준이든 미달하면 전체 실패로 처리한다.
- 답글, 삭제 댓글, 작성자 개인정보 분석은 MVP에서 제외한다.
- 댓글 원문은 외부 서버나 데이터베이스에 저장하지 않는다.
- API가 반환한 `totalResults`는 화면의 전체 댓글 수 근사치로만 취급하고 분석 분모로 사용하지 않는다.

### 3. 브라우저 내 분석
- 댓글별로 긍정, 중립, 부정과 신뢰도를 계산한다.
- 반복/스팸성 댓글과 지나치게 짧은 댓글은 핵심 인사이트 집계에서 제외한다.
- 피드백을 내용, 전달력, 편집, 음질, 영상 길이/속도, 자막, 오류 제보, 후속 요청으로 분류한다.
- 분석 결과마다 해당 판단을 뒷받침하는 대표 댓글을 최대 3개 제공한다.
- HTML 태그, URL, 제어 문자, zero-width 문자, 과도한 공백과 반복 문자를 정규화하되 원문 표시용 텍스트는 별도 보존한다.
- 이모지만 있는 댓글은 지원 감정 이모지가 있을 때만 분석하고, 타임스탬프/멘션/URL만 있는 댓글은 제외한다.
- 같은 정규화 텍스트는 하나만 집계하고 가장 높은 좋아요 수를 대표값으로 사용한다.
- 한국어·영어가 아닌 댓글과 언어 판별이 불확실한 댓글은 `unsupported-language`로 제외하며 개수를 리포트에 표시한다.
- 긍정과 부정이 혼재하거나 신뢰도가 임계값 미만이면 중립으로 분류한다.
- 욕설은 자동으로 부정으로 간주하지 않는다. 대상과 문맥이 없는 단순 감탄/친근한 표현을 구분한다.
- 개인 공격, 혐오 표현 또는 민감정보가 포함된 대표 댓글은 기본적으로 마스킹하거나 대표 근거에서 제외한다.

### 4. 자동 리포트
- 한 줄 총평과 분석 댓글 수
- 긍정/중립/부정 비율
- 잘하고 있는 점 최대 3개
- 개선할 점 최대 3개(언급량과 권장 행동 포함)
- 주요 주제와 언급량
- 다음 콘텐츠 아이디어 최대 3개
- 감정별/주제별 대표 댓글
- 수집 정렬, 수집/유효/제외 댓글 수, 부분 수집 여부와 분석 버전을 포함한 `분석 기준` 영역
- 표본이 10개 미만이면 감정 비율은 표시하되 강점/개선점 순위를 생성하지 않고 `표본 부족`을 표시한다.
- 인사이트는 `max(3개, 유효 표본의 5%를 올림한 값)` 이상의 서로 다른 댓글이 뒷받침할 때만 생성한다.
- 개선점의 권장 행동은 감지된 주제에 매핑된 사전 정의 템플릿만 사용하며, 영상 자체를 보지 않았다는 한계를 명시한다.
- 콘텐츠 아이디어는 질문/요청 의도가 있는 댓글이 최소 기준을 충족할 때만 생성한다.
- 긍정/중립/부정 비율은 반올림 후 합계가 정확히 100%가 되도록 largest-remainder 방식으로 표시한다.

### 5. 결과 보존
- 리포트는 브라우저의 `localStorage`에 최근 5개까지만 저장한다.
- 사용자는 저장된 리포트를 개별 삭제하거나 전체 삭제할 수 있다.
- 브라우저 인쇄 기능으로 PDF 저장이 가능한 인쇄 레이아웃을 제공한다.
- 저장 전 스키마를 검증하고, 손상되거나 지원하지 않는 버전의 항목은 앱 전체를 중단하지 않고 해당 항목만 폐기한다.
- `QuotaExceededError`, private browsing, 저장 차단 환경에서는 현재 리포트를 유지한 채 `기기에 저장하지 못함`을 비차단 경고로 표시한다.
- 저장 결과에는 댓글 작성자 식별자를 포함하지 않는다. 원문 댓글 저장 여부는 초기 공개 전 정책 검토 후 결정하며, 기본값은 대표 댓글만 저장이다.

### 6. 분석 제어와 접근성
- `FR-CTL-01` 수집/분석 중 사용자는 취소할 수 있고 취소 후 입력값을 유지한다.
- `FR-CTL-02` 성공/오류/취소 후 같은 URL 또는 다른 URL로 재시도할 수 있다.
- `FR-A11Y-01` 상태 변경은 `aria-live`로 알리고 포커스를 무리하게 이동시키지 않는다.
- `FR-A11Y-02` 모든 인터랙션은 키보드로 가능하며 차트와 아이콘에 동등한 텍스트를 제공한다.
- `FR-A11Y-03` 200% 확대, 360px 폭, 고대비 및 reduced-motion 환경에서 기능 손실이 없어야 한다.

## 분석 품질 요구사항
- 감정/주제 규칙은 버전 관리하고 리포트에 `analysisVersion`을 기록한다.
- 한국어와 영어 각각 긍정·중립·부정 및 각 주제의 고정 평가 fixture를 유지한다.
- 릴리스 기준: 감정 macro-F1 0.70 이상, 주제별 precision 0.75 이상을 내부 라벨 데이터셋에서 충족한다.
- 분류 신뢰도 임계값과 최소 언급 기준은 코드 상수로 중앙화하고 테스트 없이 변경하지 않는다.
- 좋아요는 최신 댓글에 불리하고 인기 댓글에 유리한 편향이 있으므로 감정 비율에는 가중하지 않는다.
- 분석 결과는 영상 품질의 객관적 평가나 전체 시청자의 의견으로 표현하지 않고 `수집한 공개 댓글 기준`으로 표현한다.

## 비기능 요구사항

### 성능
- `NFR-PERF-01` 초기 JavaScript gzip 목표는 250KB 이하(차트 제외 lazy chunk 허용).
- `NFR-PERF-02` 300개 댓글 분석은 기준 기기에서 10초 이내, main thread long task는 50ms 미만을 목표로 한다.
- `NFR-PERF-03` 썸네일과 비핵심 차트는 lazy load하고 분석 중 입력/취소 버튼은 반응해야 한다.
- `NFR-PERF-04` 네트워크 요청 타임아웃은 페이지별 10초, 전체 작업은 60초 soft timeout으로 한다.

### 신뢰성
- 한 API 페이지 실패가 이미 수집한 안전한 데이터를 손상시키지 않는다.
- 모든 비동기 결과는 `jobId`를 확인해 취소되거나 오래된 작업이 최신 화면을 덮어쓰지 못하게 한다.
- 동일 입력과 동일 분석 버전은 정렬과 API 데이터가 같을 때 동일 결과를 생성해야 한다.
- 예기치 않은 렌더 오류는 Error Boundary가 포착하고 새 분석 시작/로컬 기록 초기화 경로를 제공한다.

### 호환성
- 최신 2개 버전의 Chrome, Edge, Firefox, Safari 데스크톱 및 모바일 Safari/Chrome을 지원한다.
- Web Worker, AbortController 또는 localStorage가 없거나 차단된 환경은 해당 기능을 감지해 명시적 미지원/저장 불가 상태를 표시한다.

### 개인정보·안전·정책
- 서버 로그, 자체 분석 도구와 오류 추적 서비스로 URL, 영상 ID, 댓글 원문을 보내지 않는다.
- 외부 링크는 허용 목록 기반이며 새 창 사용 시 `rel="noopener noreferrer"`를 적용한다.
- 공개 배포 전 YouTube API 서비스 약관, 개발자 정책, 필수 고지와 개인정보처리방침 요구사항을 검토한다.
- 리포트에는 자동 분석의 한계와 댓글 작성자를 대상으로 불리한 결정을 내리는 용도로 사용하지 말라는 안내를 표시한다.

## 오류 및 에지 케이스 요구사항

| 상황 | 제품 동작 | 사용자 행동 |
|---|---|---|
| 빈 값/공백/2,048자 초과 | 네트워크 요청 없이 입력 오류 | URL 수정 |
| 지원하지 않는 YouTube 경로/호스트 | 지원 URL 예시 표시 | 올바른 영상 URL 입력 |
| 유효 형식이지만 존재하지 않는 ID | `VIDEO_NOT_FOUND` | URL 확인/다른 영상 |
| 비공개·삭제·지역/연령 제한 등으로 조회 불가 | 확인할 수 없는 영상으로 중립 표현; 원인을 단정하지 않음 | 공개 영상 사용 |
| 댓글 비활성화 | `COMMENTS_DISABLED`, 재시도 숨김 | 다른 영상 사용 |
| 공개 댓글 0개 | `NO_COMMENTS` | 다른 영상 또는 추후 재시도 |
| API 키 누락 | 운영 설정 오류; 분석 버튼 비활성화 | 운영자 설정 필요 |
| 잘못된/만료된 키, API 미활성화 | `API_KEY_INVALID` | 운영자 설정 확인 |
| referrer 제한 불일치 | `API_KEY_RESTRICTED` | 허용 도메인 확인 |
| 일일 할당량 초과 | `QUOTA_EXCEEDED`; 자동 재시도 금지 | 할당량 갱신 후 재시도 |
| 분당 제한/HTTP 429 | `Retry-After` 우선, 지수 backoff 후 최대 2회 | 잠시 후 재시도 |
| 500/502/503/504 | jitter 포함 지수 backoff 후 최대 2회 | 재시도 |
| 400 또는 `invalidPageToken` | 프로그래밍/페이지 토큰 오류; 반복 재시도 금지 | 새 분석 시작 |
| 오프라인/DNS/CORS/타임아웃 | 네트워크 오류로 통합하되 내부 진단 코드는 유지 | 연결 확인/재시도 |
| 2·3페이지 실패 | 충분한 표본이면 부분 리포트와 경고, 아니면 실패 | 부분 결과 확인/재시도 |
| 사용자 취소/URL 변경/탭 이동 | 요청과 Worker 취소; 취소를 오류로 기록하지 않음 | 다시 시작 가능 |
| 중복·스팸·짧은 댓글이 대부분 | 유효 표본 부족 안내 | 원문 표본 수 확인 |
| 지원 언어 댓글이 거의 없음 | 지원 언어 부족 안내; 잘못된 인사이트 생성 금지 | 결과 한계 확인 |
| Worker 초기화/런타임 실패 | Worker 1회 재생성; 재실패 시 분석 오류 | 재시도/지원 브라우저 |
| 메모리 부족/탭 종료 | 복구를 보장하지 않음; 기존 저장 리포트는 유지 | 댓글 수 제한 후 재시도(향후 옵션) |
| localStorage 손상/차단/용량 초과 | 현재 분석은 성공, 저장만 비차단 실패 | PDF 저장/브라우저 설정 |
| 썸네일 로드 실패 | 중립 placeholder; 분석 계속 | 조치 불필요 |
| 인쇄/PDF 취소 또는 실패 | 리포트 유지 | 다시 인쇄 |

## 성공 기준
- 지원 URL의 영상 ID 추출 성공률 100%
- 300개 이하 댓글 리포트를 일반 데스크톱 환경에서 60초 이내 생성
- 모든 인사이트에 댓글 수 또는 대표 댓글 근거가 표시됨
- 모바일 360px와 데스크톱 1280px에서 핵심 흐름 사용 가능
- 댓글이 없거나 API 오류가 발생해도 빈 리포트 대신 해결 가능한 안내를 표시
- 오류 분류 fixture의 모든 HTTP 상태/reason 조합이 정의된 제품 오류로 매핑됨
- 취소된 작업과 이전 작업의 결과가 최신 리포트를 덮어쓰지 않음
- 표본 부족 시 최소 기준을 우회한 인사이트가 생성되지 않음

## 출시 수용 기준
- [ ] 지원/비지원 URL 표의 모든 케이스가 자동 테스트를 통과한다.
- [ ] 영상 1회 + 댓글 최대 3회 요청으로 300개를 수집하며 불필요한 `search.list`를 호출하지 않는다.
- [ ] API 키 미설정, 400, 403의 주요 reason, 404, 429, 5xx, timeout, offline을 각각 재현할 수 있다.
- [ ] 1페이지 성공 후 다음 페이지 실패의 부분 성공 경로가 테스트된다.
- [ ] 300개의 긴 혼합 언어 댓글에서도 취소 버튼과 입력 UI가 멈추지 않는다.
- [ ] 리포트 수치의 분모, 반올림 합계, 제외 사유와 대표 댓글 참조 무결성이 검증된다.
- [ ] localStorage 손상/용량 초과에서도 앱이 시작되고 새 분석이 가능하다.
- [ ] 인쇄 미리보기에서 입력/버튼이 숨겨지고 카드가 불필요하게 분할되지 않는다.
- [ ] API 키 저장소 스캔, 의존성 취약점 점검, 접근성 자동 검사와 수동 키보드 검사가 완료된다.

## 제품 제약 및 전제
- URL만으로 댓글을 가져오려면 YouTube Data API 키가 필요하다.
- 정적 앱의 API 키는 사용자에게 노출되므로 Google Cloud에서 YouTube Data API만 허용하고 배포 도메인 HTTP referrer 제한 및 일일 할당량을 적용한다.
- 서버가 없으므로 비밀 API 키가 필요한 OpenAI 등의 생성형 AI API는 사용하지 않는다.
- 감정 분석 모델/사전은 최초 실행 시 브라우저에 다운로드되어 첫 분석이 이후 분석보다 느릴 수 있다.
- 자동 분석은 문맥, 반어법과 혼합 언어를 오판할 수 있으며 결과를 참고 자료로 안내한다.
